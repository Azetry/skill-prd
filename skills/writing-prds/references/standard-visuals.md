# 標準：圖、畫面與版型

讀者看圖比看字快。能畫出來的就不要只用文字和表格說。但每一張圖都要回答一個問題；沒有問題要回答的圖是裝飾，刪掉。

## 什麼時候用哪一種

| 要說明的事 | 用 | 不要用 |
|---|---|---|
| 一個畫面長什麼樣、哪裡會變 | 實際截圖，或照畫面畫的示意圖，加上號碼標註 | 用文字描述版面 |
| 現在和之後的差別 | 左右並排兩張，同樣的資料 | 兩段文字各自描述 |
| 事情照什麼順序發生、在哪裡判斷 | 流程圖 | 編號的長段落 |
| 幾個角色或系統之間誰做什麼 | 泳道圖 | 一張把所有人擠在一起的流程圖 |
| 一條流程上哪幾站會檢查、各檢查什麼 | 一站一欄的流程與檢查 | 只列規則清單 |
| 錢、資料或文件從哪裡到哪裡 | 兩端加箭頭的小圖，一種走法一張 | 表格裡寫「A 到 B」 |
| 幾個選項在同樣幾個面向上的差異 | 表格 | 圖 |
| 時程 | 甘特條或時程表，標工作天 | 只寫起訖日期的句子 |

表格適合「同樣幾個欄位、很多列」。只是把段落切成格子的表格，改回句子或改成圖。

## 畫面與標號

- 已經存在的畫面用截圖；還沒做的用示意圖。示意圖要標明是示意。
- 互動點用號碼標在圖上，圖旁或圖下照同樣的號碼寫說明。號碼只給要說明的地方。
- 一張圖最多七個號碼；更多就拆成兩張。
- 截圖和示意圖一律用示範資料：虛構的人名、公司、帳號、金額。真實的截圖先確認沒有個資，帳號類只留末四碼。
- 圖要有替代文字，說明這張圖在講什麼。

## 版型（搭配 assets/site/site.css）

建站工具附了這些 class，直接在 Markdown 裡寫 HTML 使用：

| class | 用途 |
|---|---|
| `.pair` | 左右對照：現在／之後 |
| `.spec` + `.notes` | 上面或左邊放畫面，旁邊照號碼寫說明；`<i class="pin">1</i>` 是號碼圓點 |
| `.tg` | 聊天機器人對話的示意：`.bubble` 訊息、`.kb` 按鈕列、`.me` 使用者說的話 |
| `.web` | 網頁畫面的示意：`.top` 導覽列、`.card` 卡片、`.btn` 按鈕 |
| `.hl` | 圈出這次要看的地方 |
| `.pipe` + `.stage` | 一站一欄的流程；每站的項目用 `li.stop`（擋住）、`li.warn`（提醒）、`li.ask`（要回答）、`li.log`（自動、紀錄） |
| `.lanes` | 泳道表 |
| `.cases` | 特殊情況的清單 |
| `.status` | 狀態標籤：`live` 已上線、`change` 要改、`new` 新增、`ask` 待確認 |
| `.wide` | 包住會比內文寬的表格或圖，讓它自己左右捲動 |

流程圖用 ```` ```mermaid ```` 區塊寫，建站時會畫出來。

樣式只有淺色主題。顏色只用在三處：連結、號碼圓點、狀態與檢查類型的標籤。不要為了好看加顏色、陰影或圖示。

## 檢查

- [ ] 每一頁先問過：這一頁最重要的一件事，能不能用一張圖說？
- [ ] 每張圖有一句說明，講得出它回答什麼問題。
- [ ] 圖上的字和內文、和真的畫面一致。
- [ ] 所有畫面都是示範資料。
- [ ] 在手機寬度看，頁面本身不會左右捲動；只有表格和圖在自己的框裡捲。
